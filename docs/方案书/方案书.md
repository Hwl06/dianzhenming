# 电诊明——电气设备故障诊断助手

## 1. 项目简介

“电诊明”面向实验室、工厂和电气实训场景，将设备现象、报警代码和测量值转化为结构化排查路径。它不替代持证电工，而是把经验固化为“先安全、再定位、后复核”的辅助工具，降低新手漏查风险。

## 2. 用户痛点

传统故障处理依赖个人经验：信息散落在说明书、维修记录和口头传承中；新人容易直接复位、带电拆检，或只看报警代码而忽略负载与接线。现场最需要的是下一步做什么、什么情况必须停机。

## 3. 解决方案与创新点

- 把诊断输出拆成可能原因、排查顺序、安全提醒、升级条件四块，结果可执行、可复核；
- 结合电气专业知识与 AI 对话，AI 负责理解自然语言，规则负责兜底和安全边界；
- 采用案例驱动设计，输入不完整时不编造结论，明确提示补充信息。

## 4. 技术实现

当前 v1.0.5 原型为本地 Web 应用，前端通过 `app.mjs` 调用共享规则 `rules.mjs` 和服务端。输入包括设备类型、现象、报警、结构化测量值及安全确认；输出统一包含风险、置信度、信息缺口、原因证据、排查步骤、安全提醒和升级条件。服务端提供 CSP 等安全头、请求体/字段校验、按 IP 限流和模型输出验证。

规则判定高危或断电、验电、挂牌上锁未完成时，服务端不会把请求发给联网模型。未配置千帆 API Key 时使用本地规则；联网接口不可用或结果格式错误时回退本地规则。该版本未包含 RAG 知识库。

原型新增“复制检修记录”和“下载文本报告”，把一次诊断变成可交接、可复核的记录，避免演示只停留在聊天窗口。

页面内置三类专业案例：电机三相不平衡、配电柜接点发热、变频器加速过流。结果区同步展示“本次判断依据”，让诊断过程可解释、可复核，而不是只给一个结论。

联网运行时由 `server.mjs` 代理调用百度千帆兼容接口；API Key 只存在服务端环境变量，不暴露给浏览器。没有令牌或网络异常时，自动回落到本地规则诊断。

## 5. 应用价值

可用于电气实验室巡检、实训教学、设备初筛和维修交接。典型收益是缩短“从报警到第一步排查”的时间，减少无序复位和不安全操作，并沉淀标准化维修记录。

## 6. 竞赛评分对应

创新性 30%：专业场景 + 可解释 AI + 安全边界。技术实现 30%：结构化输入、规则兜底、AI 接口预留。实用价值 20%：覆盖电机、配电柜、变频器三类常见设备。用户体验 10%：示例一键载入、结果分区清晰、移动端可用。展示效果 10%：三分钟完成“输入—诊断—安全决策—复核”闭环。

## 7. 后续迭代

第一阶段接入比赛平台并补充真实案例；第二阶段增加设备说明书/维修记录知识库；第三阶段增加 DuMate 工具调用与可追踪的诊断报告。所有新增能力都必须保留安全提醒和人工复核入口。
